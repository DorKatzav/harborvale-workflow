HARBORVALE WORKFLOW · תוכנית העבודה · 2026-09-08

תוכנית העבודה: תשע תחנות מהשלד ועד הריצה החיה

זה התרגום לעברית של PLAN.md, המסמך שממנו אני עובד. הגרסה האנגלית היא המקור: היא מכילה גם את החוזים בין המודולים (חתימות פונקציות, פורמט קבצים) שלא תורגמו כאן. כל תחנה נבנית בענף משלה, עוברת שער, מקבלת דוח עברי, ואתה מאשר את המיזוג.

מה קבוע לאורך כל הדרך (המגבלות מהתכנון)

  • החוזה הוא קובץ. צוות 2 מניח רק את dataset_contract.json ואת clean_data.csv; הכלי שלו מסרב לכל נתיב אחר.
  • שדות נמדדים בחוזה מגיעים מהכלי; הסוכן כותב רק תיאור, נימוק והנחות. המאמת מתעלם מהטקסט האנושי.
  • קבצי הדאטה (clean_data.csv, features.csv, metrics.json) זהים בייט-בייט בין ריצות: seed 42, ליבה אחת, עיגול ל-4 ספרות.
  • כישלון = עצירה. FAILED.md, צוות 2 לא רץ, קוד יציאה 2, בלי ניסיון חוזר.
  • ריקים נשמרים ומוצהרים; ההשלמה בתוך ה-Pipeline של המודל. מגדר ומצב משפחתי לעולם לא פיצ'רים.
  • כל מספר בדוחות מגיע מ-stats.json / metrics.json דרך כלי רינדור.
  • סודות רק ב-.env; המפתח עולה ל-Railway רק ב-M7. הבדיקות וה-CI לעולם לא קוראים ל-OpenAI.

01התחנות

שלד פרוס ביום הראשון

ריפו git עצמאי + GitHub ציבורי harborvale-workflow; סביבת conda harborvale עם CrewAI מוצמד; Flask עם /health; CI; שער M0; README ראשוני.

  • pytest + ruff ירוקים
  • import crewai עובד
  • סריקת סודות ריקה
  • /health חי מחזיר את ה-commit של main
אתה: יוצר שירות Railway מהריפו ב-GitHub ומדביק את הדומיין ב-.env כ-LIVE_URL.

הכלים של צוות 1: טעינה, ניקוי, EDA

בלי סוכנים עדיין. hv/ingest.py, hv/cleaning.py (מפת ישויות, כפילויות, טיפוסים, ריקים נשמרים), hv/eda.py (סטטיסטיקה + דוח HTML עם גרפים). המספרים האמיתיים של הדאטה נרשמים ביומן.

  • מספר השורות אחרי ניקוי תואם לדוח הניקוי
  • אפס "Phone" / "CC" / "COD" / "Mobile" בקובץ הנקי
  • הריקים נשמרו בדיוק
  • שתי ריצות = אותו hash
  • שיעור הנטישה בין 5% ל-50%
אתה: מוריד את הקובץ מ-Kaggle ושומר כ-data/raw/ecommerce_churn.xlsx.

החוזה והמאמת

hv/contract.py: מודל pydantic, בנייה נמדדת, שדות אנושיים מוגנים, מאמת שמריץ את כל תשע הבדיקות ומחזיר את כל הכשלים יחד, שש התקלות המוכנות, ו-scripts/break_it.py. החוזה האמיתי הראשון נבנה ומקומט.

  • הקובץ הנקי עובר את החוזה שלו
  • כל תקלה נכשלת עם הבדיקה הצפויה; שינוי יחידה מציג את רמז היחס 100
  • שינוי תיאור בחוזה לא משנה את התוצאה
  • החוזה עובר טעינה ושמירה ללא שינוי

צוות 1 ב-CrewAI

שלושה סוכנים (Data Quality Engineer, Business Analyst, Data Steward), הגדרות YAML, כלים שעוטפים את M1–M2, צוות stub לבדיקות, וריצה אמיתית עם gpt-5-mini שתוצריה מקומטים ב-artifacts/crew1/.

  • הבדיקות ירוקות בלי מפתח
  • חמישה קבצים; החוזה מאמת את הקובץ הנקי
  • הסוכן לא נגע בשדה נמדד
  • insights.md עם חמשת הסעיפים ומספרים רק מ-stats.json
  • זמן, קריאות ועלות נרשמו
אתה: מדביק OPENAI_API_KEY ב-.env.

הכלים של צוות 2: פיצ'רים, אימון, הערכה, כרטיס מודל

hv/features.py (מהחוזה בלבד, מגן דליפה), hv/train.py (רגרסיה לוגיסטית, Random Forest, HistGradientBoosting; 5-fold), hv/evaluate.py (ROC-AUC, PR-AUC, F1, precision@top-10%, הוגנות לפי קבוצה), hv/model_card.py.

  • מזהה, מטרה ומאפיינים מוגנים אינם פיצ'רים
  • המודל נטען ומנבא על שורה בצורת החוזה
  • בסיס + שלוש וריאציות ב-metrics.json
  • שתי ריצות = קבצים זהים
  • המודל המוגש טוב מהבסיס

צוות 2 + ה-Flow מקצה לקצה

שלושת הסוכנים של צוות 2 עם כלי הגבול; flow/main.py עם router ומסלול כישלון; events.jsonl + manifest.json; scripts/run_flow.py עם הדגלים. ריצה מלאה אמיתית מקומטת; ריצה מחובלת נשמרת כדוגמה.

  • ריצה מלאה: שמונה תוצרים + manifest עם hash-ים תואמים
  • ריצת stub עוברת בלי מפתח
  • ריצה עם --tamper unit_change: צוות 2 לא רץ, FAILED.md, exit 2
  • כלי הגבול מסרב ל-data/raw/
  • קבצי הדאטה של הריצה המקומטת זהים לריצת stub טרייה

האתר: חמישה דפים + לוח "שבור את זה", פרוס

Flask + Jinja + CSS משלנו (שפה עיצובית נבחרת כאן). דפים: בית, אנליסטים, החוזה (עם לוח השבירה), מדעני נתונים, ריצות. POST /api/validate מריץ את המאמת על עותק מחובל תוך שנייה.

  • כל הדפים 200 ב-URL החי
  • לוח השבירה החי מחזיר סירוב עם רמז היחידה
  • קובץ תקין מקבל אישור חי
  • צילומי מסך בדוח

ריצה חיה מאחורי סיסמה

עבודת רקע בתוך Flask, לוג זורם לדף (SSE), ריצה אחת בכל רגע, דף /runs מציג ריצות שרת. רק עכשיו המפתח עולה ל-Railway.

  • בלי סיסמה: 401
  • ריצה מלאה בשרת מסתיימת והלוג הופיע בדף
  • ריצה שנייה בזמן ריצה: 409
  • המפתח לא בהיסטוריית git
אתה: מגדיר APP_PASSWORD ו-OPENAI_API_KEY כמשתני Railway.

סגירה

README עם מבחן הזר (שכפול, ריצה, שבירה, ריצה שנייה), ביקורת אדברסרית עם סוכני Opus על המאמת וה-Flow, דוח סיום עברי, יומן ואובסידיאן סגורים.

  • כל השערים M0–M7 ירוקים בריצה טרייה
  • מבחן הזר עובר משכפול נקי

אופציונלי: Supabase

העלאת הקובץ הנקי וטבלת ריצות; דף הריצות קורא משם. רק אם נשאר זמן אחרי M8.

02הפרוטוקול לכל תחנה

  1. ענף feat/m<N>-<slug> מ-main מעודכן.
  2. פסקת פתיחה בשפה פשוטה: מה התחנה עושה ולמה.
  3. בדיקות ליד הקוד; קומיטים קטנים.
  4. python scripts/gate.py --m N חייב להדפיס PASS. מתקנים, לא מדלגים.
  5. דוח עברי docs/reports/M<N>_HE.html, מאומת RTL בדפדפן.
  6. סיכום אנגלי קצר בטרמינל.
  7. אובסידיאן: דף הבית, פתק התחנה, יומן, החלטות.
  8. PROJECT_LOG.md; push; PR; CI ירוק; אתה קורא את הדוח ומאשר את המיזוג; אימות שהאתר נפרס מחדש.
